> 在 CVTE 做算法实习的这几个月，我参与搭建了一套"课堂学生行为分析"系统：从课堂视频里自动识别每个学生什么时候在看书、练习、举手、听讲。这篇文章复盘整个项目的技术路线、我踩过的坑，以及我独立设计的一个小算法——双阈值滞回事件合并。

## 系统全貌：一条五级流水线

系统的目标听起来简单：输入一节课的课堂录像，输出每个学生的行为时间轴。但拆开看，它是一条五个环节的流水线：

![全流程流水线（实习汇报 PPT 原图）](/images/cvte/ppt_pipeline.png)

- **T05 检测 + 追踪**：逐帧检测学生人体并分配追踪 ID，输出帧图片 + 关键点 JSON；
- **T08/T09 事件提取**：把逐帧的检测结果聚合成有起止时间的行为事件；
- **T07 VLM 行为识别**：把事件片段的图片送给视觉语言大模型（VLM）做行为分类；
- **T06 人工校验**：我开发的 Web 标注工具，让标注员在预标注结果上快速修正；
- **Evaluate 评测**：用时间区间 IoU 匹配计算 Precision / Recall / F1，问题回流驱动下一轮优化。

（T05~T09 是脚本的历史编号，不代表流程顺序——实际数据流就是上面这个顺序。）

我的工作贯穿了整条链路：跑通流水线、优化每个环节、建评测体系。下面挑几个最有技术含量的部分讲。

## 检测追踪：YOLO 多任务检测 + BoTSORT 追踪

检测器是基于 **YOLO 的多任务模型**（公司内部数据训练），一次前向同时输出人体框、14 个人体关键点、头部框和 8 个行为分类分——这意味着很多行为判定可以直接用检测器的输出，不必每个框都调一次大模型。

追踪用的是 **BoTSORT**（通过 BoxMOT 库集成）：卡尔曼滤波预测轨迹位置，匈牙利算法做数据关联，还能叠加 ReID 外观特征解决遮挡后 ID 漂移的问题。

这里有一个工程上的衔接问题：BoTSORT 内部虽然会做检测与轨迹的关联，但它对外只输出框和 ID，检测器顺带算出的关键点、行为分并不会跟着轨迹出来。所以流水线里需要把两者缝合——**追踪器给 ID，检测器给属性**，用 IoU 匹配把每个追踪框关联回当帧的原始检测结果：

```python
def match_detection_info(track_box, tracker_score, detections, *, min_iou=0.5):
    """将追踪框与检测结果匹配，并优先使用检测的细节信息"""
    best_iou, best_det = 0.0, None
    for det in detections:
        iou = bbox_iou(track_box, np.asarray(det.get("body_box"), dtype=np.float32))
        if iou > best_iou:
            best_iou, best_det = iou, det
    return {
        "iou": best_iou,
        "det": best_det if best_iou >= min_iou else None,  # 匹配不上就退回追踪器输出
    }
```

## 踩坑三连：GPU 闲置、OOM、环境依赖

跑通流水线的过程，本质上是连续排障的过程，三个坑印象最深：

1. **GPU 在睡大觉**。检测器是 ONNX 模型，但环境里只装了 CPU 版 onnxruntime，推理全在 CPU 上跑。换成 `onnxruntime-gpu` 后整体大幅提速。教训：**先 profiling，再谈优化**。
2. **16GB 内存被 2054 个任务撑爆**。事件扫描阶段一次性提交所有任务，大图全缓存在 future 里，进程直接被 kill。根因是"一次性提交、内存无界"，改成**分批提交 + 消费后显式释放**后稳定跑完。
3. **flash_attn 与 PyTorch 版本不兼容**。首次加载失败污染了 CUDA 显存，重试也失败，而且用了哪种 attention 完全不透明。我把它改成显式的三级模式（flash_attn / sdpa / auto），加载前检测、失败干净退出。

## 标注工具优化：让预标注"看得顺、改得快"

核查预标注结果时暴露的第一个问题，其实是工具本身。原版标注页面有三个明显的效率短板：**信息分散**——左侧做标注、右侧看图，VLM 预标注和人工标签显示在不同区域；**操作繁琐**——每个事件都要"点标签 → 点保存"两步走；**进度不可见**——统计信息只有纯文字列表，无法直观判断整体进度和各类别分布。

![原版标注界面：标注区与看图区分离，统计只有纯文字列表（人脸已遮挡）](/images/cvte/label_web_before_masked.png)

我重写了标注页面（FastAPI + 内嵌前端），针对性逐项解决：把看图、VLM 预标注、人工标注整合到同一视图，一眼对比机器结果和人工判断；**数字键直接选标签**，标注完自动跳转到下一个事件；新增**"不确定"标记**（U 键），拿不准的样本先标记、事后回流复查，不用强行下结论；进度和各类别分布改成可视化柱状图，标注到哪儿、哪类样本还缺，一目了然。

![改进版标注界面：同屏对比、快捷键操作、"不确定"标记、可视化进度统计（人脸已遮挡）](/images/cvte/label_web_after_masked.png)

## 提示词优化：给系统性混淆"打补丁"

VLM 行为分类的初版提示词是标准套路：角色设定 + 10 类行为定义 + 输出规则。跑完预标注后，我把误判样本逐一翻了一遍，发现错误不是随机的，而是**集中在几对固定类别之间**——比如"看书"和"练习"反复互判（区别只在于有没有握笔书写），"东张西望"和"认真听讲"分不清（转头幅度多大才算张望）。

我的做法是针对这些高频混淆对优化提示词：把每对类别的**判别特征**写进定义里（比如"练习 = 手拿着笔在纸上书写"，判定前先看有没有笔、有没有书写动作）。优化后几类系统性误判明显下降。

但这条路有个副作用：补丁越打越多，**提示词字数明显变长**——所有类别的细节堆在一起，模型的注意力被稀释，重点信息反而可能被淹没。mentor 针对这个问题给了我一个更优雅的建议：**两段式级联提示词**——第一级用一个简短的"粗提示词"做初步分类；当结果落入已知的易混淆对（比如判为"看书"或"练习"）时，再路由到第二级专门针对这对类别的详细提示词做最终裁决。这样每个提示词都保持短小聚焦，判别细节只在真正需要的地方展开。这也让我意识到：提示词工程和写代码一样，"一个大而全"往往不如"路由 + 各司其职"。

## 我的独立设计：双阈值滞回事件合并

初版事件提取的逻辑是"攒满 N 帧就切一个事件"，问题很明显：一个真实行为经常跨越切割点，事件被硬截断；VLM 偶尔的误判也会混进来。

我的改进思路分两阶段：**密集滑动窗口逐帧预测**（该推才推——静止复用标签省算力，运动尖峰强制推理），再用**双阈值滞回（Hysteresis）**把密集预测平滑成干净的行为段。滞回的思想像一个"有黏性的开关"：一个标签要**连续出现够久**（min_duration）才被确立为有效事件，防短时抖动误报；确立后**短暂中断**（≤ max_gap）又出现，就桥接回同一段，防碎片化：

```python
diffs = np.diff(timeline)              # 相邻预测点的时间间隔
split_mask = diffs > tau_split         # 间隔超过低阈值 → 切开
segments = split(timeline, split_mask)
for start_ts, end_ts in segments:
    if end_ts - start_ts >= tau_merge: # 持续超过高阈值 → 确立为事件
        events.append(ActionEventRecord(action, start_ts, end_ts))
```

效果对比如下图：原始预测里的单帧毛刺被"溶解"，小空洞被"桥接"，最后得到一整段干净的"看书"行为。

![双阈值滞回核心（实习汇报 PPT 原图）](/images/cvte/ppt_hysteresis.png)

还有一个细节顺序很关键：**必须先桥接、后溶解**。比如"看书 90s | 听讲 30s | 看书 90s"，如果先溶解（假设 min_duration=120s），两段 90s 都会被各自杀掉；先桥接则能合成 210s 的有效事件。

## 收获

这段实习让我从"会调模型"变成了"会交付系统"：**问题驱动**——所有优化都来自真实标注中暴露的问题，不凭空设计；**根因定位**——OOM、事件截断都是靠定位根因解决，而不是反复试；**设计权衡**——攒帧切分 vs 滞回合并、标注平台 vs 评测脚本，按场景选方案，也认清每个工具的适用边界。
